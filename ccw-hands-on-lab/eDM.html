Claude Code는 개인의 생산성 도구에서 팀의 개발 프로세스를 구성하는 요소로 자리를 옮기고 있습니다. 이 단계의 논의는 기능보다 운영에 가깝습니다. 어디까지 권한을 허용할지, 사용량과 비용을 어떤 지표로 파악할지, 검증된 방식을 어떻게 팀에 배포할지를 이틀에 걸쳐 순서대로 다룹니다.

Day 1은 개인 환경에서 조직 표준으로 확장하는 흐름입니다. 아키텍처와 설치, 헤드리스 실행(Chapter 1)에서 시작해 역할별 서브에이전트(Chapter 2), managed-settings 기반의 정책 통제와 OpenTelemetry 관측(Chapter 3), 스킬과 플러그인 형태의 팀 스타터 킷 배포(Chapter 4)로 이어집니다.

Day 2는 자동화와 측정, 통합에 집중합니다. Chapter 5에서 Claude Code를 파이프라인 구성 요소로 전환하고, 토큰 효율과 메터링을 강의와 데모로 다룬 뒤, 오후 캡스톤에서 이틀간의 결과물로 실제 접속 가능한 서비스를 배포하고 하네스 엔지니어링까지 적용해 봅니다. 이론과 실습을 같은 비중으로 배치했으며, 전 과정은 참가 조직의 환경과 과제에 맞추어 구성한 맞춤형 워크샵입니다.

CH 04Settings, 나의 Claude Code를 팀의 플랫폼으로

설정 스코프와 권한 규칙 → Hooks와 MCP → LAB 커스텀 커맨드와 스킬, 통합 자유 실습

혼자 쓸 때 편했던 설정은 팀에 그대로 옮기면 충돌합니다. settings.json의 user / project / managed 세 스코프가 어떻게 겹치고 누가 이기는지 실험으로 확인하고, allow / deny / ask 권한 규칙을 세 단계로 대조합니다. Hooks로 편집 직후 검사를 자동으로 걸고, MCP 서버를 붙여 외부 시스템을 도구로 편입시킵니다. 마지막 랩의 규칙은 하나입니다 - 파일을 손으로 짜지 말고 Claude에게 시켜서 팀 스타터 킷을 만드는 것. 완성된 킷은 플러그인으로 묶어 배포하면 동료는 설치 한 줄로 같은 환경을 갖습니다.
